# S3 传输核心（尚未接入应用界面）

当前提供桶范围的 `S3Endpoint` / `S3Client` 核心 API，不在连接菜单中展示未完成的 S3/R2 入口。原生连接表单、Keychain、共享队列、递归、同步、预览和重启恢复的适配仍需完成；现有 FTP/SFTP/WebDAV 用户工作流继续使用原来的协议客户端。

## 已实现的边界

- 路径式端点、区域、Access Key / Secret Key；可携带已有 Session Token，尚未获取或刷新 IAM Role 凭据。端点资料与分片清理记录为非秘密 Codable 数据，凭据单独传入，不在 URL 中携带。
- CryptoKit SHA-256 / HMAC 实现 SigV4；签名包含 Host、所有传入条件头、Content-MD5 与 x-amz 字段。libcurl 保留原始路径且不尝试 Basic/Digest、不跟随重定向；严格 TLS 验证，明文仅允许 loopback 测试。
- ListObjectsV2 以 `/` 分隔前缀，按 S3 URL/query 规则解码对象、前缀与分隔符（`+` 是空格，`%2B` 是加号），逐页原样传递不透明 continuation token。对象键按 UTF-8 字节识别，不归一化 `.`、`..`、重复斜杠、Unicode NFC/NFD；对象与同名前缀分别识别。空路径分量显示 `/`。当前文件夹的标记不作为子文件展示。
- 单页 XML 最多 4 MiB / 32,000 节点 / 24 层，拒绝实体、异常命名空间、重复字段、重复对象与不完整分页。全目录最多 100,000 项 / 32 MiB 估算元数据；超限提示浏览更具体的前缀。
- HEAD/ETag 版本核对、If-Match GET 与 Range 内容摘要。下载先核对远程 SHA-256，再写自己创建的 0700 暂存目录；完成校验后使用现有原子提交，不默认覆盖本地文件。
- 非空文件上传使用 multipart（最低 8 MiB 分片、自适应至最多 10,000 片，源文件最多 5 TiB），每片从原文件精确切片，256 KiB 缓冲预读计算 SHA-256 与 Content-MD5，不创建整份上传副本。源文件身份/大小/时间戳在预读前后及最终提交前核对。
- 空文件使用带摘要的条件 PUT；新对象 If-None-Match `*`，明确覆盖已有对象使用原 ETag 的 If-Match。非空上传只在条件 CompleteMultipartUpload 成功、XML 根/桶/键/ETag 合法后返回成功；HTTP 200 的 Error XML 也会拒绝。
- 原生传输支持当前会话暂停/继续、限速和取消；取消/失败独立 abort 自己的 upload ID。abort 失败返回非秘密 `S3MultipartCleanup` 记录，可用重新认证的同桶客户端重试。该记录尚未接入应用的持久清理列表。

## 验证与空间管理

`scripts/test_core.sh` 包含 AWS 官方 GET、PUT、Lifecycle、List 四个确定签名样例，以及编码、Unicode 字节身份、XML 边界测试。

```sh
./scripts/test_s3.sh
```

脚本先清理上一次 Swift 产物，从固定 MinIO 源码提交 `7aac2a2c5b7c882e68c1ce017d8256be2feea27f` 编译测试服务，再用独立 Python 标准库签名器准备 1,008 个对象。真实 HTTPS 测试覆盖超过 1,000 项分页、中文/特殊字符、大小不同的多分片、空文件、证书/名称/密钥拒绝、Range/旧 ETag 拒绝、并发创建/覆盖拒绝、暂停继续、取消保护、源截短与分片清理。

MinIO 为独立 AGPLv3 测试进程，不链接、不嵌入 app；需要 Go 1.24+，不是生产依赖。源码及 Go 模块/编译缓存只放在本项目 `.build/s3-fixture-build`，编译后立即移除；测试脚本退出时删除 `.build/s3-fixture` 程序。测试凭据、证书、数据、日志仅存在于自建临时目录，finally 停止服务并移除。手动清理测试服务产物使用 `python3 scripts/clean_generated.py fixtures`，不会删除开发 app 或用户的文件。

## 仍待验收与限制

- 没有用 AWS/R2/DreamObjects 实际账户验收；隔离 MinIO 成功不代表这些服务全部兼容。R2 区域、端点及条件 multipart 行为必须在真实服务单独核对，不能通过降级无条件覆盖来绕过失败。
- 不包含桶发现/创建、虚拟主机式端点、服务商预设、IAM Role 获取/刷新、OAuth、复制/重命名、递归删除、版本选择、ACL 或 SSE/KMS。
- Multipart 尚无重启保留/恢复；当前取消会 abort，不承诺保留进度。网络响应丢失时可能无法确定最终提交状态，只报告失败/未确认成功，不回滚可能已经提交的目标。
- 若服务在 InitiateMultipartUpload 后未提供有效 upload ID，无法确定可安全清理的对象；不能猜测或批量删除其他上传。
- 原始键编码/Unicode 区分已有核心测试；MinIO 与 macOS 文件系统的特殊键、同名对象/前缀、Unicode 兼容限制仍需实际 AWS/R2 与应用浏览/落盘测试。
- 此版本 loopback MinIO 的根列表展示 `same` 对象时未同时展示 `same/` 前缀；独立签名请求得到同一结果。客户端不臆造服务未返回的前缀。同名对象/前缀的解析已有单元测试，真实云服务仍待验收。
- 尚未完成应用 GUI、完整故障注入、R2/WAN 性能、长期能耗与完整 Transmit 对齐验收；没有发布安装包或公开性能承诺。
